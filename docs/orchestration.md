# Orchestration ledger

The orchestrator's record of work units. It is the memory across context compaction: after one, re-read this file and `docs/progress.md` before doing anything else. Measured results live in `docs/progress.md`; this file tracks who is doing what.

Status values: `planned | running | review | merged | blocked-owner | blocked-dep`. Gate values: `holds | open | pending-owner | pending-time`.

Last updated: 2026-11-18.

## Authority settings in force

- Merging (changed by the owner on 2026-11-18): no pushes for now, because each push stops for the owner's permission. Work is committed locally and may go straight to `main`. Units still get their own branch and the same review and checks before the orchestrator merges them into local `main`. CI runs only on GitHub, so nothing committed after this point has had CI until pushing resumes; the orchestrator runs lint, typecheck, test, build and, where the image can be affected, the local image build and budget check instead.
- Not yet on GitHub: local `main` from the commit "Spikes B and C: spec edits from findings, decisions in the progress log, ledger" onward. PR #14 (that commit) and PR #12 (the first version of P0-2c) are open there and were left as they are. Unit branches exist locally only (`phase0/contracts-db`, `phase0/corpus-*`, `phase0/review-rescoring`, `phase0/spike-a-transport`, `phase0/spike-d-judge`); their content is squashed into `main`.
- Concurrency: at most 4 implementation subagents.
- Phase checkpoints: stop and report to the owner at each phase exit.
- Spend: no paid services or keys unless the owner provides them in the session.
